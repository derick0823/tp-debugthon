- 回答什麼：**臺北 456 個里，哪些先做老屋健檢？權重換了，順序會不會變？**
- 作者：debug-cc，2026-10-22 夜。統籌：MVP專案經理。設計原型，不是交件產品。
- 題目要求逐條對照：[REQUIREMENTS.md](REQUIREMENTS.md)。

## 頁面有什麼

1. **第一屏**：左邊地圖依目前名次上色，右邊前 20 名長條。上方 5 支權重滑桿（高齡、老屋、液化、救災、軟弱層），拉動時地圖與排行即時重排，有 CSS transition。
2. **不確定性**：每個里畫一條名次範圍線（隨機權重 2,000 次的第 5～95 百分位），圓點是目前權重下的名次。右上角寫「幾個里不論權重都穩在前 46 名」。
3. **點一個里**：5 格因子等級色塊、一句白話、「排進前 46 名」的機率條。
4. **下半段**：雙老長條（50 年以上老屋比例 2025／2035／2045）、穩定前段里清單。方法、因子定義、用途、限制收在 `<details>`。
5. **匯出**：「下載 456 里排名 CSV」，內容是目前權重的完整排名。**給市府排程用，不是逐棟鑑定**：按鈕下方與 CSV 第一行註解都寫這句（peer M6）。
6. 網址記住權重，例如 `#w=4,1,1,0.5,1`。加 `#more` 會捲到下半段。
7. **第二個分頁「公辦都更候選」**（`#tab=renew`）：另一張表，不跟滑桿變。地圖與清單標出「風險高、房價低、住戶老、市場沒動」4 項都符合的里，每里一句「為什麼要公辦」。

## 公辦都更候選的規則

統籌建議的規則有兩處我改了，理由寫在下表。

| 條件 | 門檻 | 和建議不同的地方與理由 |
|---|---|---|
| 風險 | 等權前 120 名 | 同建議 |
| 房價低 | 每坪中位數在全市後 1/3（≤ 66.0 萬） | 改用 `village_unit_prices_net.csv`。毛價版含新成屋，新成屋本身就是「市場有在動」，會和第 4 項混在一起。只看前 3 項時，毛價版 8 個里、淨價版 10 個里【實測】 |
| 高齡 | 65 歲以上比例前 1/3（≥ 26.8%） | 同建議 |
| 市場沒動 | `weilao_active_est` 低於中位數 1.36，而且 `lvr_share_newbuild` 是 0 | 建議用 E3 的「現有都更案 0 件」。當時 E3 只有 3 列對到里，所以改用 marts 已有的危老與新成屋訊號。10/22 02:30 E3 補齊（461 案落到 190 個里），但它只含 168 專案，不是全部都更案，所以仍只在卡片顯示件數，不參與篩選。4 個候選里中，新和里有 1 案，其他 3 里 0 案【實測】 |

結果【實測，`data/meta.json`】：4 項都符合 4 個里（萬華騰雲、新安、新和，文山興業），差 1 項 22 個里。萬壽、富福、富民、頂碩風險排前 10，但危老已有 3～5 件，所以不列公辦。

## 市場錯位圖（公辦分頁，2026-10-24 加）

問題：房子看起來最危險的里，有沒有分到相應的危老與都更案？用我們自己的資料算（`build_data.py` 的 `market_gap()`，結果在 `data/meta.json` 的 `market_gap`）。網址加 `#tab=renew,gap` 直接捲到這張圖。

- 分組：房子面 3 個因子（老屋、軟弱層、液化）各用本頁既有的等級，取 4～5 級的里（全市最高 7%，各 32 個里）。
- 基準：門牌棟數占比。
- 危老：`weilao_active_est`，851 件（有效核准案 899 件中落得到里的），107-07～115-09 核准，危老核准清冊 1151002 版。路段分攤到里，是**推估**。
- 都更：`uro-cases/out/uro-review-cases.csv` 中已核定的第一次擬訂案 172 案（2017-01～2026-09 核定），用 `uro-review-case-villages.csv` 的權重落里。只含 168 專案。

| 因子 4～5 級（32 里） | 房子棟數 | 危老案 | 都更案 | 合計 | 每千棟件數（全市 4.9） |
|---|---|---|---|---|---|
| 老屋 | 6.0% | 1.9% | 0.6% | **1.7%** | 1.4 |
| 軟弱層 | 5.6% | 8.7% | 10.5% | 9.0% | 7.9 |
| 液化 | 7.3% | 12.6% | 13.4% | 12.7% | 8.5 |

結論【實測，2026-10-24】：**老屋比例最高的 32 個里，有全市 6.0% 的房子，只分到 1.7% 的危老與都更案。** 軟弱層、液化最高的里沒有這個落差，案子反而偏多。老屋等級由低到高，每千棟分到 5.6、4.9、3.9、1.4 件。三項平均分組時沒有落差（最高組房子 5.5%、案件 7.4%），所以頁面只講老屋這條軸。

限制：因果方向不確定，已改建過的里老屋比例自然變低【推論】；老屋比例是戶數加權推估，已知屋齡不足 20 棟的里用區中位數。

## 資料與方法

| 項目 | 來源 | 證據等級 |
|---|---|---|
| 5 因子百分位、等級、名次區間 | `data/marts/village_rankings.*`（`pipelines/build/build_village_rankings.py`） | 程式產出 |
| 因子原值 | `data/marts/village_indicators.csv` | 見 marts README |
| 雙老長條 | `data/marts/building_points.parquet` 的 `built_year` | 【推估】 |
| 里界 | 內政部國土測繪中心 115/8/17 版，簡化 8 m | 【原始】 |

1. 網頁的分數＝Σ（權重×因子百分位）÷Σ 權重。
2. 百分位用排名程式的 `factor_table` 與 `pct` 重算，不用 marts 裡四捨五入後的 `f_*`。四捨五入會產生並列，百分位最多差 0.017【實測】。
3. 等權時，網頁分數與 `composite_equal_city2019` 最大差 5.2e-5【實測，`data/meta.json`】。
4. 液化只用城市版 2019（`*_city2019`）。全國 2026 版不上這頁。
5. 雙老長條只用有實際建成年的 70,326 棟（全市 209,350 棟），並假設現有房子都不拆【推估】。

## 已知限制

1. 這是里與里之間的相對排名。它不說「這個里會不會倒」。
2. 老屋與軟弱層是推估。判不出屋齡的棟多半是小棟，不是隨機缺漏。
3. 已知案例（海砂屋、黃單）不能當驗證集，AUC 0.37 與 0.50【文件，`data-patterns/report.md`】。本頁沒有外部驗證。
4. 公辦分頁沒有算公有地、已劃定更新地區、地籍。房價是成交樣本，不是存量。
5. 無頭 Edge 捲動後截圖會留白，所以下半段用高視窗截圖。
