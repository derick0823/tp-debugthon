# 【待補：作品名稱】

**臺北老屋地震風險：先查自己家，再排全市。**

一個網站、兩個入口。市民輸入地址，看「我家危險嗎」與「下一步找誰」；市府看「哪些里不論怎麼算都排在前面」。

- 作品網址：【待補：GitHub Pages 網址】
- 參加：市政 debug松 2026，第 6 題「危老耐震如何查，風險評級怎麼找」
- 隊伍：【待補：隊名】

## 為什麼做這個

臺北面臨「人老＋屋老」：老房子多，住在老房子裡的人也老了。市府要排出老屋健檢與公辦都更的優先順序，卻排不出來：

- **逐棟屋齡不開放。** 81% 的戶查不到任何開放的逐棟屋齡，官方統計只分「30 年以上／未滿 30 年」。
- **風險彼此無關，加不起來。** 在臺北，土壤液化和「高齡×老屋」幾乎沒有關係（相關係數約 0）。硬加成一個總分，會把只在某一項很危險的地方藏起來。
- **過去的地圖排不出順序。** 2010 年的臺北里層級風險地圖，435 個里有 382 個落在「中等」。
- **市場改建避開最危險的地方。** 危老重建核准案中，萬華核准少、失效多、推進慢。
- **市民的查詢入口要消失。** 臺北市土壤液化潛勢查詢系統 2026-10-31 停止服務。

## 怎麼用

### 市民：我家危險嗎

輸入地址，看到一張卡：

| 卡上的項目 | 說明 |
|---|---|
| 建成年與耐震規範世代 | 依建成年分成不同的耐震規範時期，不是只看屋齡 |
| 土壤液化 | 城市版與全國版各自的等級，以及兩版是否一致 |
| 一樓軟弱層候選 | 例如連棟騎樓街屋。這是候選，不是判定 |
| 救災條件 | 這個里有沒有列管的窄巷、消防通道 |
| 這個里在全市的相對位置 | 五個因子各一格，1～5 級 |
| 市府列管 | 只有輸入的地址正好在官方清冊上才顯示，並附清冊原文與官方連結 |
| 下一步 | 一般戶、高齡戶各一欄：免費顧問、耐震初評、補強補助、電梯補助、危老、防災型都更 |

**卡上每一項都標「已確認」「推估」或「未判定」。**未判定會寫原因，例如「沒有成交紀錄」。

### 市府：哪些里不論怎麼算都在前面

| 視圖 | 說明 |
|---|---|
| 五因子並排 | 高齡、1999 年前老屋存量、液化、救災不便、一樓軟弱層候選，各自一張地圖，**不給總分** |
| 權重滑桿與排名區間 | 拉滑桿看排名怎麼變；每個里附排名區間（2,000 組隨機權重） |
| 液化版本切換 | 城市版與全國版一鍵切換，顯示兩版一致度 |
| 高齡化最快的地方 | 內湖、士林、北投等 1980 年代近郊 |
| 救災可及性候選 | 窄巷、高液化、80 歲以上比例都高的里，附理由 |
| 一頁里況說明 | 選一個里，產出可以貼進公文的段落，附資料來源與統計截止日。給承辦人回覆議員與陳情用 |

**排完順序之後：**「不論權重怎麼調都排在前面」的里，可以當市府依《都市更新條例》第 7 條第 1 項第 2 款「迅行劃定」更新地區的候選。迅行劃定讓都更的同意門檻從 3/4 或 4/5 降到人數、面積各過半，市府自己就能啟動，不用修中央法律。

## 這不是什麼（請先讀）

- **這是事前排序，不是耐震鑑定。**官方的耐震初評滿分 100 分，用公開資料只估得到其中約 17～22 分。結果只能幫市府決定先去哪裡做正式評估，不能代替專業技師。
- **「推估」不是事實。**屋齡推估來自不動產成交紀錄，只有交易過的建物才有，小棟老屋常常查不到。
- **液化等級是區域尺度**，不是這一棟的鑑定。
- **等級是相對的。**卡上的等級是「和臺北市其他里比」的結果，不是「幾分以上就危險」。

市民卡片最上面一行固定寫：

> 標「推估」的項目是本站用公開資料推算的，不是政府的耐震評估；標「已確認」的項目照抄市府清冊原文。這張卡不代表這棟房子安全或不安全。

我們不寫「本站不保證資料正確」這類籠統免責。波特蘭案中，市府自己的不保證聲明被拿來證明清冊不可信；所以我們改成逐項標明資料是推估還是照抄官方原文。

### 為什麼公開風險資訊

我們考慮過公開的副作用：房價、標籤化、屋主反彈。兩份研究的結果：

| 研究 | 方法 | 結果 |
|---|---|---|
| 政府研究計畫（GRB 12691655） | 2016 年臺北市公告液化潛勢前後比較 | 中高潛勢區房價相對下跌：前後各 3 個月比較 −15.2%，各 6 個月比較 −7.2% |
| 本隊分析（實價登錄 2013～2026 年，20.9 萬筆） | 事件研究，以 2015 年為基準 | 高潛勢區 2016～2018 年平均約低 5%，逐年都**不顯著**；2019 年後差距消失 |

兩份研究方向一致：影響存在，但規模小、時間短。我們的做法：

- 市民只能查自己輸入的地址，不提供可以逐棟瀏覽的風險地圖。
- 市府列管的海砂屋與地震列管建物，只在輸入的地址正好在官方清冊上時才顯示，並附清冊原文與官方連結。這些都是官方已經公開到門牌的資料，我們只是指回官方文件。
- 我們自己在網站上公布，不要求屋主做任何標示。美國波特蘭 2019 年曾要求屋主在門口貼地震危險標示牌，被法院以「強迫屋主替政府說話」擋下；法院同時指出，由市府自己在網站公布是比較好的做法。
- 卡片一定接到「下一步」：申請耐震初評、補強補助。研究發現，屋主願不願意補強和風險知覺無關，和同棟鄰居的態度、房子是否已損壞有關。所以我們不叫屋主去都更，只告訴他可以找誰。

依據：`research/issue-06/city-workflow/g1-disclosure-wording.md`、`research/issue-06/data-patterns/g1-price-effect.md`、`research/issue-06/world-practices/city-workflow/g1-portland.md`。

## 資料與資安原則

做技術要同時顧到資訊安全與個人資料。我們的原則：

1. **只用開放資料，以及授權相容的資料。**每一份的授權判定見 `docs/data-licenses.md`。授權沒確認的資料不放上公開網站。
2. **公開網站是純靜態網頁。**沒有後端程式、沒有資料庫、沒有登入。
3. **我們這一端不蒐集、不保存個人資料。**不要求姓名、電話、電子郵件，也不存查詢紀錄。
   - 地址比對在使用者的瀏覽器裡完成。使用者先選行政區，瀏覽器只下載該區的資料檔（1.5～4.4 MB），伺服器只看得到「下載了哪一區」。
   - 公開版不用網址參數傳地址。隊內原型為了 Demo 支援網址參數，只在隊內主機使用，且該主機的網頁伺服器不記錄網址參數。
4. **第三方服務會看到什麼，我們照實說。**地圖底圖向 OpenStreetMap 的伺服器下載圖磚，對方看得到你的 IP 與瀏覽的地圖範圍。網站放在 GitHub Pages，GitHub 依它的隱私權政策處理連線紀錄。這兩者不在我們控制之內，所以我們不說「完全不留紀錄」。
5. **不做可以逐棟瀏覽的列管地圖。**海砂屋與地震列管資訊，只在輸入的地址正好在官方清冊上時顯示，並附清冊原文與官方連結。
6. **推估一律標「推估」。**
7. **內部完整資料不離開隊伍。**含授權未確認欄位的完整版資料只在隊內主機使用，不放上公開網站，也不放進公開的程式碼庫。
8. 程式採 MIT 授權，我們產出的資料採 CC BY 4.0。

## 我們想過、但這次沒做的

這次聚焦在「查自己家」與「排全市」。以下方向我們研究過，理由都留著，可以是下一步：

| 方向 | 為什麼這次沒做 |
|---|---|
| 單一加權總分 | 風險彼此無關，總分會藏住危險的里；紐西蘭 2026 年也因此廢掉單一分數 |
| 里層級的「市場不做」地圖 | 需要地籍圖；這次只做區層級 |
| 承辦人案件追蹤系統 | 要接市府內部系統，寫進上面的 100 天建議 |
| AI 從街景推估屋齡 | 臺灣缺可用的訓練資料，一天做不完 |
| 可瀏覽的列管建物地圖 | 我們只在輸入確切地址時指回官方清冊，不做讓人逐棟瀏覽的地圖 |
| 重建工地鼠患外溢 | 和排優先順序距離較遠；市府 2026-05 已有新制 |

完整的議題庫：`research/issue-06/IDEAS.md`。
