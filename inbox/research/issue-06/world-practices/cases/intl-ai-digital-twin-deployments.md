# 國際：政府實際導入的 AI 建物篩檢與城市數位分身（世界銀行、日本 PLATEAU、東京、新加坡）

- 檔名代號：intl-ai-digital-twin-deployments
- 查核日：2026-10-17
- 對應痛點：
  - P1：PLATEAU 的建物屬性來自日本法定的「都市計畫基礎調查」，是「政府怎麼把逐棟屋齡與構造變成開放資料」的直接對照。
  - P3：世界銀行的住宅韌性計畫把「判斷哪間房子危險」接到「補助誰」。
  - P4：PLATEAU 的地震模擬把結果呈現成「道路閉塞率」，正好是窄巷救災的問題。
- 解法類別：資料、技術
- 制度起始年：PLATEAU 2020；東京都數位分身 2020 前後；世界銀行住宅韌性計畫約 2019；最近一次重大變動：2026（PLATEAU 標準規格 5.1 版）

## 一句話

日本 PLATEAU 的建物年代與構造來自法定調查，不是 AI 猜的；它的規格裡沒有耐震欄位。

## 背景痛點

- 各國都想知道「哪些房子在地震時會倒」，但逐棟現場勘查太貴【推論】。
- 兩條路線：
  1. 用 AI 從空拍或街景影像推估建物特徵（世界銀行）。
  2. 把政府既有的調查資料做成 3D 城市模型，再接模擬（日本、東京）。
- 本檔只寫「政府真的導入了什麼、效果如何」。用 AI 推估臺北逐棟屋齡的技術細節由 C4 任務負責（`research/issue-06/codex/prompts/c4-building-age-proxies.md`）。

## 做法

### 1. 世界銀行全球住宅韌性計畫（Global Program for Resilient Housing）

- 由全球減災與復原基金（GFDRR）支持【文件】[1]。
- 五步驟：無人機、街景相機與機器學習測繪 → 機器學習萃取建物特徵（材料、高度、窗數、車庫門開口）→ 共享住宅資料平台 → 設計補助與融資 → 政府支持【文件】[1]。
- 各國用途【文件】[1]：
  - 瓜地馬拉：辨識並標出地震時有倒塌風險的建物。
  - 秘魯：替市政府做自動化房產估價與脆弱度評估。
  - 哥倫比亞：支援「Casa Digna, Vida Digna」住宅改善補助。
  - 聖露西亞：評估五級颶風下的屋頂受損風險。
  - 荷屬聖馬丁：估算擴大住宅韌性計畫的成本。
  - 印尼、墨西哥：把韌性放進住宅補助計畫。

### 2. 開放城市 AI 挑戰賽（Open Cities AI Challenge）

- GFDRR 主辦，2020 年 3 月結束【文件】[2]。
- 用 12 個非洲城市與地區的高解析無人機影像，超過 70 萬棟建物，請參賽者做建物輪廓分割【文件】[2]。
- 這是**建模競賽**，不是政府部署。產出的是開源模型與訓練資料【推論】。

### 3. 日本 PLATEAU（國土交通省）

- 2020 年啟動，目標是全國城市的 3D 城市模型與開放資料【文件】[3]。
- 2021 年度開放 56 個城市，預計 2025 年度末擴大到約 300 個城市【文件】[3]。
- 標準製品規格書 5.1 版，2026-03-19 發布【文件】[4]。
- 民間與自治體在上面做應用（use case），每年度有一批實證計畫【文件】[5][6]。

### 4. 東京都數位分身實現計畫

- 東京都數位服務局主辦。路線圖第 3 版定義 2030 年的目標狀態：3D 城市模型等「城市基礎資料」持續更新，讓都、企業、都民的決策與政策制定能用上【文件】[7]。
- 三個階段，時間軸標示 FY2020、FY2023、FY2027、FY2030【文件】[7]。
- 五個重點領域：防災、都市營造、交通、環境、產業【文件】[7]。
- 3D 檢視器持續加圖層。2026-08-28 新增地質柱狀圖與土質試驗結果；2026-09-25 更新小笠原村 3D 地圖【文件】[7]。

### 5. 新加坡 Virtual Singapore

- 新加坡國家研究基金會主導的全島 3D 數位分身，常見報導預算約 7,300 萬新幣【待確認：官方頁面網址已失效，未取得一手來源】。
- 新加坡沒有地震問題，用途偏向規劃、日照、通風、人流模擬【待確認】。

## 機制細節

### PLATEAU 建物屬性從哪來

- 建物詳細屬性 `uro:BuildingDetailAttribute` 的定義：「依都市計畫法實施的**都市計畫基礎調查**所蒐集的建物基礎資訊」【文件】[4]。
- 也就是說，**建物的構造與年代來自法定、定期的政府調查**，不是 AI 推估【文件】[4]。
- 主要欄位【文件】[4][8]：

| 欄位 | 意思 | 值 |
|---|---|---|
| `bldg:yearOfConstruction` | 建築年 | 西元年 |
| `uro:buildingStructureType` | 構造種別 | 601 木造・土藏造、602 鋼骨鋼筋混凝土、603 鋼筋混凝土、604 鋼骨、605 輕量鋼骨、606 磚造・混凝土磚造・石造、610 非木造、611 不明 |
| `uro:fireproofStructureType` | 耐火構造區分 | 1001 耐火、1002 準耐火、1003 其他、1011 不明 |
| `uro:totalFloorArea` | 總樓地板面積 | m² |
| `uro:buildingStructureOrgType` | 各城市自訂構造分類 | 城市自建代碼表 |
| `uro:serialNumberOfBuildingCertification` | 建築確認申請編號 | 字串 |
| `uro:vacancy` | 是否空屋 | 代碼 |
| `uro:surveyYear` | 建物利用現況調查的實施年 | 西元年，**必填** [1..1] |

- **沒有耐震欄位**：我們抓了規格書 4.2.3.2 節（建物擴充屬性）的 13 個子頁，沒有任何一頁出現「耐震」二字【實測】[4]。
- 災害風險屬性只有：河川洪水、內水、海嘯、高潮、蓄水池、土砂災害【文件】[4]。**沒有地震或液化類別**。
- 規格書把「都市自訂分類」與「全國標準分類」分開存。城市可以保留自己的細分類，全國又能比較【文件】[4]。

### PLATEAU 上的地震應用（2025 年度實證）

**A. 建物振動模擬系統 v3.0（靜岡市、埼玉縣戶田市）**【文件】[5]

- 從 PLATEAU 取建物構造、建築年代、高度，輸入地震動，算最大層間變形角。
- 依木造、非木造的門檻判定全倒或半倒。
- 驗證：用熊本地震地震動重現益城町，和內閣府防災的木造、非木造被害函數比較，「確認同等精度」。
- 輸出兩種：地圖（倒塌數、道路閉塞率的熱圖）與儀表板（全倒、半倒、應急組合屋需求戶數、閉塞道路數）。
- **道路閉塞率**：用國土地理院道路資料，依路寬分 3 級（未滿 3 公尺、3～5.5 公尺、5.5 公尺以上），算道路中心線兩側 10～50 公尺內的倒塌棟數，參考內閣府南海海槽被害想定的方法做簡易機率評估。
- 隱私：自治體表示**逐棟被害想定因個資與隱私難以公開，改用「道路區段閉塞率」比較好公開**。
- 使用者回饋：約 40% 認為模擬結果可用於業務，約 60% 認為道路閉塞率可用，約 30% 認為組合屋估算可用。願意正面考慮導入的只有約 30%。使用者還想要海嘯、液化等連鎖災害資訊。

**B. 衛星資料大規模震災建物被害推估（石川縣金澤市）**【文件】[6]

- 用 PLATEAU LOD1 的建物輪廓與高度當震前基準，和震後 SAR 衛星推估的高度比對。
- 大型 SAR 覆蓋率 100%；小型 SAR 在建物密集區因拍攝角度問題只有 22%，低於預期的 30%。
- 從發災到交付結果約 1 週。4 成受訪者希望更快。
- 自治體認為可改變「等民眾申請」的罹災證明流程。

### 世界銀行計畫的部署模式

- 重點不是 AI 本身，而是**把影像判讀接到補助計畫**：先找出哪些房子可補強，再接政府補助與民間資金【文件】[1]。
- 計畫頁只說可以「用一小部分成本、一小部分時間」完成，沒有公布準確率、評估戶數或單戶成本【文件】[1]。

## 批評與失敗

1. **世界銀行沒公布準確率**：計畫頁只有「省成本、省時間」的說法，沒有準確率、評估戶數、單戶成本，也沒有結果數字。「成果」欄列的是活動，不是成效【文件】[1]。瓜地馬拉、秘魯的模型準確率【待確認：GFDRR 的機器學習指引與案例 PDF 被伺服器擋下（403），無法讀取】。
2. **競賽分數不等於部署效果**：開放城市 AI 挑戰賽的 0.86 Jaccard 是建物輪廓分割，不是耐震脆弱度判定【推論】。
3. **數位分身多是展示**：PLATEAU 地震模擬的實證中，願意正面考慮導入的自治體職員只有約 30%【文件】[5]。使用者要求精度要超過內閣府被害想定，並能對第三方說明科學根據【文件】[5]。
4. **衛星 AI 在密集區失準**：金澤實證中，小型 SAR 在建物密集區覆蓋率只有 22%【文件】[6]。臺北老舊巷弄比金澤更密，問題可能更大【推論】。
5. **數位分身不等於有耐震資料**：PLATEAU 規格沒有耐震欄位；災害風險屬性也沒有地震與液化【實測】[4]。3D 外觀做得再好，也回答不了「這棟有沒有做過耐震補強」【推論】。
6. **硬體門檻**：東京都 3D 檢視器建議 Intel Core i7 第 13 代以上、32GB 記憶體【文件】[7]。高齡屋主幾乎不可能用【推論】。
7. **Virtual Singapore 公開成效資料少**：官方頁面網址已失效，查不到一手的使用成效【待確認】。

- 2026-03-31：PLATEAU 2025 年度實證成果公開，包含建物振動模擬 v3.0（加入道路閉塞率與組合屋估算）、衛星震災被害推估、豪雪地帶除雪優先度與震災現場支援【文件】[5][6]。
- 2025～2026：東京都數位分身路線圖更新到第 3 版，目標年 2030【文件】[7]。
- 2026：GEM 臺灣曝險模型的重建成本改用「多個 AI 模型推估再加專家判斷」【文件】見 `intl-gem-openquake-hazus.md` [1]。這是 AI 在國際風險模型中的實際用法：估成本，不是判定單棟耐震【推論】。

## 對臺北的可轉移性

- 可以借：
  - **PLATEAU 的資料路線**：日本的逐棟構造與年代來自法定定期調查，再標準化成開放格式。臺北對應的是房屋稅籍與使照資料。這直接支撐 S4「市府應開放稅籍屋齡與構造」的論點【推論】。
  - **「都市自訂分類 + 全國標準分類」雙欄設計**：臺北的構造別可以保留原始代碼，另加一欄對應到國際分類（例如 GEM 分類）【推論】。
  - **道路閉塞率當公開單位**：日本自治體認為逐棟被害難公開，道路區段比較好公開【文件】[5]。臺北的 185 筆消防通道清冊只有里名，可以先做「里層級窄巷比例」，未來有路寬圖資再做路段【推論】。
  - **路寬 3 級**：未滿 3 公尺、3～5.5 公尺、5.5 公尺以上【文件】[5]。可以直接用來分臺北巷弄【推論】。
  - **世界銀行「判讀接補助」的流程**：風險地圖的終點是補助名單，不是地圖本身【推論】。
- 不能直接借（為什麼）：
  - 3D 數位分身：3 人到 10/24 做不出來，也沒有逐棟資料可放【推論】。
  - 街景 AI 判讀：準確率未公開、密集區會失準；而且是 C4 的範圍【推論】。
- 前提條件：
  - 逐棟資料要由市府開放，數位分身才有意義【推論】。
  - 要有驗證集。PLATEAU 用熊本地震益城町的實際被害驗證【文件】[5]。臺北的 R1 已發現海砂屋、黃單不適合當驗證集【文件】PLAN.md R1 H6。
- 對應解法方向：
  - S4（主要）：PLATEAU 證明「政府調查 → 標準化 → 開放」是可行路線，日本已做到約 300 城。
  - S5：道路閉塞率與路寬 3 級，是救災可及性的現成指標設計。
  - S2：世界銀行的「找出可補強的房子 → 接補助」流程，可以當地址查詢結果頁的下一步設計。

## 可以直接抄的設計細節

1. **建物資料欄位表（仿 PLATEAU）**：S4 的「建議開放欄位」直接列：

   | 欄位 | 對應 PLATEAU | 臺北可能來源 |
   |---|---|---|
   | 建築年 | `bldg:yearOfConstruction` | 房屋稅籍、使照 |
   | 構造種別（標準） | `uro:buildingStructureType` | 稅籍構造別，對應到國際分類 |
   | 構造種別（市自訂） | `uro:buildingStructureOrgType` | 稅籍原始代碼 |
   | 總樓地板面積 | `uro:totalFloorArea` | 稅籍 |
   | 使照或建照編號 | `uro:serialNumberOfBuildingCertification` | 建管處 |
   | 耐震評估結果 | （PLATEAU 沒有） | 耐震初評、詳評結果 |
   | 調查年（必填） | `uro:surveyYear` | 資料更新年。PLATEAU 把它設為必填，讓使用者知道資料多舊【文件】[4] |

   - 最後兩列是臺北可以「超越 PLATEAU」的地方【推論】。
2. **路寬分級**：未滿 3 公尺／3～5.5 公尺／5.5 公尺以上。地圖用三種線寬或顏色【文件】[5]。
3. **公開粒度原則**：逐棟結果不公開，公開到「路段」或「里」。這句寫進隱私說明【文件】[5]。
4. **結果呈現兩種形式**（仿 PLATEAU 振動模擬）：地圖（熱圖）＋ 儀表板（數字卡：高風險里數、涉及高齡人口數、窄巷比例）【文件】[5]。
5. **AI 標示**：任何推估值旁邊放「推估」標籤，滑過去寫推估方法與已知誤差。世界銀行沒公布準確率，這正是要避免的【推論】。
6. **硬體門檻**：不要做 3D。用 2D 地圖加卡片，手機能開【推論】。東京都 3D 檢視器要 32GB 記憶體就是反例【文件】[7]。
