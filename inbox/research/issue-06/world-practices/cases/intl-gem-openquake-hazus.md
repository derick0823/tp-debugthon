# 國際：GEM 全球地震風險模型、OpenQuake 與美國 Hazus 的建物存量推估

- 檔名代號：intl-gem-openquake-hazus
- 查核日：2026-10-17
- 對應痛點：
  - P1：GEM 與 Hazus 都是「沒有逐棟資料，用普查統計推估建物分布與構造」的標準做法。臺北的處境完全相同。
  - P5：GEM 已經用主計總處普查替臺灣做了區層級的建物曝險模型，數字和市府說法可以互相對照。
- 解法類別：資料、技術
- 制度起始年：Hazus 1997（地震模組）；GEM 基金會 2009、全球風險模型 2018；最近一次重大變動：2026（GEM v2026.0.0，臺灣模型改版）

## 一句話

GEM 已用主計總處普查替臺北推估約 24 萬棟住宅與耐震設計等級，用屋齡換算耐震等級正是國際標準做法。

## 背景痛點

- 地震損失模型需要「每棟房子是什麼構造、幾層、哪年蓋」。全世界幾乎沒有城市有完整逐棟清冊【推論】。
- Hazus 手冊明說：大部分住宅、商業、工業建物**不逐棟計算**，而是在普查區或普查街廓內彙總、分類【文件】[6]。
- GEM 要做全球模型，只能拼接各國普查與在地研究，做成「由下而上的馬賽克」【文件】[2]。

## 做法

1. **GEM 全球曝險模型（Global Exposure Model）**：住宅、商業、工業三類。每一筆「資產」是一群屬性相同、位置相近的建物，不是單棟【文件】[1]。
2. **GEM 建物分類法（GEM Building Taxonomy）**：用一串代碼描述建物，例如 `CR/LFINF/CDL+ERM/H:2-5/RES`。v2026 改用第 4.0 版【文件】[1]。
3. **OpenQuake 引擎**：GEM 的開源計算引擎，跑危害、曝險、易損性三者結合的損失模擬。授權 AGPL-3.0【實測】[4]。
4. **Hazus 一般建物存量（General Building Stock，GBS）**：用人口普查的住宅資料、結構清冊（NSI）推估每個普查區各用途、各構造的樓地板面積、棟數與價值【文件】[6]。
5. **用建造年代換算耐震設計等級**：Hazus 依州別訂「基準年」，把建物分到無規範（Pre-Code）、低規範、中規範、高規範【文件】[6]。GEM 的臺灣模型也有同樣的四級（CDN、CDL、CDM、CDH）【實測】[1]。

## 機制細節

### GEM 臺灣曝險模型（v2026.0.0）

- 住宅資料來源：主計總處 2020 年人口及住宅普查，用戶籍統計更新到 2023 年【文件】[1]。
- 普查提供的欄位：住宅單位數、**建造期間**、**構造材料**、**樓層數**、是否空置【文件】[1]。
- 空間粒度：**行政區第 2 級（鄉鎮市區）**，再用網格拆到 0.01 度（約 1 公里）【文件】[1]。
- 戶數換棟數：用**臺北市稅籍資料**推出「住宅單位 → 建物」的換算係數【文件】[1]。
- 重建成本：「由多個 AI 模型推估，再結合專家判斷」，並以臺北市在地資料校正【文件】[1]。
- 商業、工業用 2011 年工商普查的事業單位數，本版沒更新【文件】[1]。
- 經緯度欄位**不是單棟位置**，是空間拆分演算法產生的點，仍代表彙總資產【文件】[1]。
- 每個建物類別都對應到 GEM 全球易損性模型的易損函數【文件】[1]。

### GEM 建物分類代碼怎麼讀（以臺灣前幾大住宅類別為例）

| 代碼 | 意思 |
|---|---|
| `MR/LWAL` | 加強磚造，承重牆 |
| `CR/LFINF` | 鋼筋混凝土構架，含填充牆 |
| `MUR` | 無筋磚造 |
| `CDN` / `CDL` / `CDM` / `CDH` | 耐震設計等級：無／低／中／高 |
| `ERN` / `ERL` / `ERM` / `ERH` | 設計地震力：無／低／中／高 |
| `H:2-5` | 地上 2～5 層 |

- 代碼意思依 GEM README 的巨分類說明與分類法術語【文件】[1]；細項代碼的中文對譯是本研究的解讀【推論】。

### Hazus 的推估邏輯

- Hazus 6.0 用 2022 年國家結構清冊（National Structure Inventory，NSI）、2020 年人口普查、主要為 2022 年的價值資料。估值改在結構層級更新【文件】[6]。
- NSI 還沒全國覆蓋的地方，仍用 Hazus 的「權重係數」把普查住宅數分配到各構造【文件】[6]。
- 地震模型用**普查區**當最小單位；洪水模型可到**普查街廓**。在街廓層級改用途對照，不會影響其他用普查區的模型【文件】[6]。
- 用途 → 構造的對照表依州分「西部」「東部」兩組【文件】[6]。
- 耐震設計等級的基準年（海嘯模組表 5-23）【文件】[6]：

| 州 | 無規範 | 低規範 | 中規範 | 高規範 |
|---|---|---|---|---|
| 加州 | 1940 前 | 1941–1975 | 1976–1994 | 1995–2000（2001 後為特高） |
| 華盛頓州 | 1955 前 | 1956–1974 | 1975–2003 | 2004 後 |
| 奧勒岡州 | 1974 前 | 1975–1994 | 1995–2000 | 2001 後 |
| 波多黎各 | 1974 前 | 1975–1994 | 1995–2005 | 2006 後 |

### Hazus 自己說的精度定位

- 只用內建基礎資料的分析：「不確定性很大」，「主要適合初步評估，以及在研究區之間做粗略比較，最小單位是普查區」【文件】[7]。
- 基礎分析可用來「比較、初步評估、協助找出可能的減災行動，對評估補助優先順序有用」【文件】[7]。
- 使用者補上在地清冊，結果可「大幅改善」【文件】[7]。

### GEM 全球模型的範圍

- 只算**地震動**。不含海嘯、**液化**、山崩、震後火災【文件】[2]。
- 只算住宅、商業、工業建物；學校、醫院、基礎設施不在內【文件】[2]。
- 用 10 萬年的事件模擬做事件式分析【文件】[2]。
- 授權：曝險模型 CC BY-NC-SA 4.0（不可商用）；空間拆分版要另外申請【文件】[3]。

## 批評與失敗

1. **耐震等級是推估，不是調查**：GEM 臺灣住宅有 48.6% 被歸為「無耐震設計」【實測】[1]。這是用建造期間與構造套對照表得到的模型假設【推論】。臺灣 1974 年後已有耐震規範，這個比例可能偏高，需要和 C 系列任務的法規年表對照【推論】。
2. **粒度只到區**：GEM 臺灣模型的住宅資料到鄉鎮市區（Adm 2）【文件】[1]。它不能回答「哪個里危險」，只能回答「哪個區的存量組成是什麼」【推論】。
3. **不含液化**：GEM 全球模型不算液化【文件】[2]。臺北盆地的液化風險要另外處理【推論】。
4. **Hazus 基礎資料精度有限**：手冊自己說只適合粗略比較【文件】[7]。Remo 與 Pinter（2012）在美國中部檢驗 Hazus-MH 地震模組【文件】[9]；搜尋摘要提到對觀測損害高估 68%～221%【待確認：未讀原文】。
5. **Hazus 平台負擔重**：7.0 版改綁 ArcGIS Pro【文件】[8]。地方政府要授權與 GIS 人力【推論】。
6. **授權限制**：GEM 曝險模型不可商用，空間拆分版要申請【文件】[3]。黑客松作品若要商業化會卡住【推論】。
   - 授權是 CC BY-NC-SA 4.0，含 ShareAlike（相同方式分享）條款【文件】[3]。活動建議作品用 MIT 或 CC BY 4.0。併進我們的開源資料會產生授權衝突【推論】（整合者 debug-83 於 2026-10-17 指出）。
   - 結論：**只能當對照數字引用，不併進我們的開源資料集。**
   - 公開的 summaries 只到 Adm1。臺北市只有一個總數（242,883 棟），沒有各區數字【文件】[1]。GEM 內部用的普查來源到 Adm2，但公開檔沒有 Adm2 的數字。

## 對臺北的可轉移性

- 可以借：
  - **「建造年代 → 耐震設計等級」對照表**：Hazus 的基準年表與 GEM 的 CDN/CDL/CDM/CDH 是國際通用做法。臺北可以用實價登錄的建成年、2001 年後使照，套臺灣耐震規範修訂年份，得到「推估耐震等級」【推論】。年份要等 C 系列任務提供。
  - **GEM 臺北區層級數字當對照組**：我們自己算的各區住宅棟數，可以和 GEM 的 242,883 棟比對，標出差異【推論】。
  - **Hazus 的自我定位句**：「適合粗略比較與排補助優先順序，不適合逐棟判定」。這句可以直接當我們的免責聲明【文件】[7]。
- 不能直接借（為什麼）：
  - 直接跑 OpenQuake 或 Hazus 算損失：需要易損函數、地盤資料、逐區構造分布。3 人 1 週做不完，而且 Hazus 只有美國資料【推論】。
  - GEM 的空間拆分點位不是真實建物位置【文件】[1]，不能拿來疊里界當里層級資料【推論】。
- 前提條件：
  - 臺灣耐震規範修訂年表（C 系列任務）。
  - 區層級「建造期間 × 構造 × 樓層」交叉表（主計總處普查）。GEM 已經用過，代表這份資料存在且可取得【文件】[1]。
- 對應解法方向：
  - S1：把「推估耐震等級」當建物側因子，取代單純屋齡【推論】。
  - S4：GEM 用了臺北市稅籍資料做換算【文件】[1]。這證明稅籍屋齡資料存在、國際研究機構拿得到。可以寫進「市府應開放稅籍屋齡」的建議【推論】。

## 可以直接抄的設計細節

1. **耐震等級推估欄位**（仿 Hazus 基準年表）：

   | 推估等級 | 條件（範例，年份待 C 任務確認） |
   |---|---|
   | 無規範 | 建成年 < 第一次耐震規範年 |
   | 低規範 | 第一次 ≤ 建成年 < 第二次修訂 |
   | 中規範 | 第二次 ≤ 建成年 < 921 後修訂 |
   | 高規範 | 建成年 ≥ 921 後修訂 |

   - 介面上這一欄要叫「推估耐震設計等級」，滑過去顯示「依建成年推估，非實際檢測」。
2. **資料粒度標籤**（仿 GEM 的 ADM_LEVEL 欄）：每個因子在介面上標粒度：逐棟、里、區。區層級資料用斜線紋理或淡色，提醒使用者這是區值【推論】。
3. **GEM 對照卡**：在「方法」分頁放一張卡：「GEM 2026 推估臺北市住宅 242,883 棟、約 252 萬人。我們的估計是 X 棟。差異來自……」。這能回應「你們的數字可信嗎」【推論】。
4. **三時段人口**（仿 GEM v2026 的 OCCUPANTS_DAY / NIGHT / TRANSIT）：高齡者白天在家比例高。救災可及性（S5）可以標「夜間人口」與「日間在家高齡人口」兩種情境【推論】。
5. **免責聲明句**（改寫自 Hazus 手冊）：「本工具使用統計資料推估，適合比較里與里之間的相對狀況、排出健檢優先順序；不能判定單一建物是否安全。」
