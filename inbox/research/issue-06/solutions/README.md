2. 幫研究者做判斷。研究者不確定要不要做、怎麼取捨時，問協調者，不等使用者。

4. 給研究者有邊界的任務。每個任務附完成條件。研究者做完回路徑，不寫說明。

協調者不做的事：

- 不替研究者重做研究。研究者的報告是正本，協調者只讀、只問、只判斷。

## 2. 怎麼聯絡協調者

- 用 `SendMessage` 傳給 `debug-40`。
- 一個議題一則訊息。不同議題分開傳。
- 大東西放檔案，訊息只給路徑。不要貼整份內容。
- 每個主張標證據等級：【實測】（附方式與時間）、【文件】（附網址或路徑）、【推論】、【待確認】。
- 【推論】不要當事實往下推。

## 3. 狀態簡報格式

每個 session 第一次聯絡時傳這份。最多 15 行。

```text
- 我是誰：<session 名>，負責 <R1／R2／R3／整合>
- 做完：<結論一句話＋檔案路徑>（每項標證據等級）
- 做一半：<項目＋預計完成時間>
- 卡住：<卡在什麼，需要誰>
- 我認為最重要的 3 個發現：<一行一個，附路徑>
- 48 小時內我還能做：<2～3 項>
```

協調者收到後存到 `briefs/<session>-YYYY-MM-DD.md`，並 commit。

## 8. 順序與避免重工

1. 任務板只有一份：`research/issue-06/solutions/BOARD.md`。只有協調者改它。研究者用訊息更新。
2. 開始任何新工作之前，先看任務板。板上沒有的工作，先傳給 `debug-40` 登記，登記後再做。
3. 一個任務只有一個負責人。別人的任務不要動手，只能把建議傳給負責人。
4. 一份檔案只有一個人寫。要改別人的檔案，傳訊息給檔案的負責人。
5. 做完自己那一輪，負責人通知協調者。協調者把「輪到誰」改成下一棒。
6. 任務之間有先後時，任務板的「等什麼」欄會寫出來。前一棒沒完成，後一棒不要先做。
