## 0. 一句話

做一個靜態網站，同一份資料、兩個入口：市民輸入地址看「我家危險嗎」，市府看「哪些里不論怎麼算都排前面」。不給單一總分。每一筆都標已確認、推估或未判定。

## 2. 聚焦：一個網站、兩個入口、四個視圖

### 2.1 入口一：市民「我家危險嗎」（S2）

輸入地址，回一張卡。卡上每一項都標「已確認／推估／未判定」，未判定要寫原因（沒有交易紀錄、沒有使照、比對失敗）。

| 卡上的項目 | 來源 | 標記 |
|---|---|---|
| 液化：全國 2026 版等級、城市版等級、兩版一致 | `building_points` | 已確認（圖資） |
| 屋齡與規範世代 g1～g6 | 使照（2001 後）或實價登錄 | 已確認／推估／未判定＋原因 |
| 一樓軟弱層候選 A／B | R3c 規格 | 只寫「候選」 |
| 這條路有沒有列入窄巷、搶救困難 | 消防清冊 | 已確認 |
| 這個里的五因子相對等級 | `village_rankings` | 相對於臺北其他里 |
| 這個地址是否在市府列管清冊（海砂屋、黃單）：只在精確門牌比對時顯示，附清冊原文地址、版本、官方頁連結；里層級另給件數 | 清冊 | 已確認（BD10） |
| 下一步：一般戶／高齡戶兩欄，列健檢、初評、補強補助、重建的資格與入口 | R2b | 文件 |

為什麼聚焦：資料支持度最高（R1 H6）；soil.taipei 10/31 關站，入口有真空；投票的是市民。反面教材：波特蘭的標示牌被法院擋下，主因是強迫屋主說出政府的話；法院點名市府自己在網站公布才是可行做法。所以我們自己公布官方已公開的清冊，內容和清冊原文一致，不做可瀏覽的列管圖層，只在精確地址查詢時顯示（BD10）。

### 2.2 入口二：市府「哪些里不論怎麼算都在前面」（S1）

| 視圖 | 內容 | 來源 |
|---|---|---|
| 五因子並排 | 五張小地圖，各自 5 級，不給總分 | `village_rankings` |
| 權重滑桿＋排名區間 | 滑桿只重算加權和；排名區間（p05／p50／p95）預先算好；標出「穩定前 N」與「被總合藏起來的 72 個里」 | c8 R1b 已算 |
| 液化版本切換 | 全國 2026 版預設，城市版切換，一致度圖例 | R1 H3 |
| 下一波雙老 | 55～64 歲比例 × 1980 年代建物 | R1 新規律 |
| 救災可及性清單（S5） | 37 個里，附中文理由；每里列窄巷、液化、80 歲以上 | c8 R1b |
| 一頁里況說明 | 任選一里，印出一頁：五因子、數字來源與年份、已知案件、進行中危老案。給承辦人回議員與陳情用（A6 輕量版） | 同一份資料 |

為什麼聚焦：這一層沒有人做過（K5）；三份研究獨立指向同一個形狀（因子分開、權重可調、區間）；「一頁里況說明」用同一份資料回答使用者加的「公務員減壓」，不另開產品。

### 2.3 README 的「100 天落地」（S4）

寫三條市府內部已有、只要彙總就能開放的資料：房屋稅籍彙總到里（TELES 已有前例）、90 年前使照批次開放、已做的初評結果分布。再寫一條流程：跨都更處與建管處的單一案件追蹤。每條寫局處、資料、成本。

### 2.4 技術形狀

純靜態。456 個里的 GeoJSON 只有 1.3 MB，Leaflet 或 MapLibre v5 直接讀。21 萬棟門牌點切成「區＋路」分片 JSON 給地址查詢。沒有後端、沒有資料庫、不碰 TGOS。部署兩處：內網 VM 給隊內看（nginx 容器），公開版放 GitHub Pages 給投票者看。細節見 `surveys/k7`、K8（在 workspace，見 BOARD）。
