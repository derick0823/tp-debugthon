## 一頁摘要

**做什麼**：一個網站，同一份資料，兩個入口。市民輸入地址，看「我家危險嗎」與「下一步找誰」。市府看「哪些里不論權重怎麼調都排在前面」，一鍵印出一頁里況說明。

**為什麼能贏**：

1. 沒有人做過「排優先順序」這一層。臺灣已有三張屋齡地圖、兩套液化查詢、一套國家級震損模型，全部是查一棟或畫一張。2024 年總統盃建研所隊最接近，只做工程面，沒有高齡、沒有救災、沒有排序輸出。
2. 國外正在放棄單一總分。紐西蘭 2026 年廢掉單一分數；東京的總合分數藏了 20 個高風險町丁目。臺北 2010 年做過的里層級 AHP 地圖，435 個里有 382 個落在「中等」，排不出順序。我們把五個因子分開顯示，給排名區間，找出不論怎麼算都在前面的里。
3. 投票的是市民，不是評審。活動沒有評審，線上票選前三名。市民會投「和我家有關」的東西。soil.taipei 10/31 關站，連液化查詢的入口都要換，剛好有真空。

**憑什麼可行**：資料層已經做完。456 個里的五因子排名與排名區間、209,350 棟的逐棟表（68% 有年份）、17 項補助與申請入口的卡片文字，全部在 `data/marts/` 與研究資料夾。前端是純靜態網頁，不需要後端與資料庫。

**要你決定的三件事**：見第 7 節。

## 2. 方案：一個網站、兩個入口

### 入口一：市民「我家危險嗎」

輸入地址，30 秒內看到一張卡。每一項都標「已確認、推估、未判定」，未判定會寫原因。

| 卡上的項目 | 例子 |
|---|---|
| 這棟的建成年與耐震規範世代 | 「推估 1975 年，1974 年以前的規範，當時尚無地震力規定」或「未判定：2012 年後沒有成交紀錄」或「依鄰棟推估 1970～1985 年」 |
| 液化 | 「城市版：高。全國 2026 版：中。兩版只有一版判高。區域尺度，不是這棟的鑑定。」 |
| 一樓軟弱層候選 | 「A 型候選：連棟騎樓街屋。這是候選，不是判定。」 |
| 這條路與這個里的救災條件 | 「本里有 3 條列管窄巷。」 |
| 這個里在全市的相對位置 | 五個因子各一格，1～5 級，相對於臺北其他里 |
| 市府列管 | 只有輸入的地址正好在官方清冊上才顯示：「已確認：建管處 115.3.25 海砂屋清冊。清冊地址：⋯。」附官方頁連結 |
| 下一步 | 一般戶與高齡戶兩欄：免費顧問、耐震初評（市府補 1.2 萬）、補強補助（補 50%，最高 1,200 萬）、電梯補助（高齡戶補 80%）、危老、防災型都更、液化自主檢查。每張有資格、金額、截止日、入口 |

### 入口二：市府「哪些里不論怎麼算都在前面」

| 視圖 | 看到什麼 |
|---|---|
| 五因子並排 | 五張小地圖：高齡、1999 年前老屋存量、液化、救災不便、一樓軟弱層候選。各自 5 級。沒有總分。 |
| 權重滑桿＋排名區間 | 拉滑桿看排名怎麼變。每個里有排名區間（2,000 組隨機權重算的）。城市版下只有 5 個里在 90% 以上的權重組合都進前 46。等權總分會藏掉 72 個里，這些里另列一張清單。 |
| 液化版本切換 | 城市 2019 版與全國 2026 版，一鍵切換，顯示兩版一致度。 |
| 高齡化最快 | 內湖、士林、北投這些 1980 年代近郊，高齡化最快、海砂屋最多。只看「已經老」的模型會漏掉它們。 |
| 救災可及性候選 | 37 個里同時有窄巷、高液化、80 歲以上比例高，附中文理由。國際上處理「救災進不去」的案例最少，這是差異化。 |
| 里況段落產生器 | 選一個或多個里，產出能直接貼進府函的句子，每段附統計截止日與來源；加補助資格與金額、危老案分階段件數。推估類因子不進公文。依據：16 則議員書面質詢的市府答復，最常寫的是日期與期程、法規條號、全市件數、既有措施、補助金額，只有 1 則用到里層級數字。另有一頁列印版。附加用途一：場勘前預檢。承辦人到現場前先看窄巷、規範世代、無電梯、列管與案件重疊，帶著問題去，不取代到場（24 個場勘驗證項目中，我們的資料有 6 項、部分 9 項）。附加用途二：給前線協力廠商用。市民入口的結果卡與下一步卡，讓接電話的人 10 分鐘內答得出來，少轉一通給承辦。都更處已發包線上 QA 客服系統，所以我們不做問答機器人，只做「這個地址、這個里的公開現況卡」給前線看。轉出線畫在「能不能就這個案子下判斷」：一般規定與公開現況前線答，案子能不能過才轉承辦（Belfast 值班規劃員也是 15 分鐘上限）。每次答覆自動帶資料版本與日期，留一份紀錄，避免日後「當初說可以」的爭議（英國 Haringey 的教訓）。 |

### 排序之後能做什麼：迅行劃定

都更條例 §7 已經有「只對危險地區降門檻」的現行法。市府依 §7 第 1 項第 2 款「為避免重大災害之發生」迅行劃定更新地區，事業計畫同意門檻從 3/4 或 4/5 降到人數、面積各過半，權利變換與代為拆除（§43、§57）可用。劃定走都市計畫程序，市府自己能做，不用修中央法律【實測 debug-aa 讀全國法規資料庫】。所以「不論權重怎麼調都排在前面」的里，就是迅行劃定的候選清單。這是排序的政策出口。

### README 的「100 天落地」

三條市府內部已有、只要彙總就能開放的資料：房屋稅籍彙總到里（國震中心 TELES 早就這麼做）、民國 90 年以前使照批次開放、已做的耐震初評結果分布。一條流程：跨都更處與建管處的單一案件追蹤。一條政策：用排序結果啟動 §7 迅行劃定。每條寫局處、資料、成本。

### 技術形狀與資安

純靜態網站，沒有後端、沒有資料庫、沒有帳號。456 個里的資料只有 1.3 MB；地址比對在瀏覽器裡做，使用者先選區、瀏覽器只下載該區的門牌分片，地址字串不離開瀏覽器。資安與個資（一位公務員的提醒，使用者 10/18 轉述）：只用開放資料與授權相容的資料；不蒐集姓名電話；不存查詢紀錄，公開版的網址不帶地址參數；不做可瀏覽的逐棟列管地圖，精確地址查詢才顯示官方清冊原文並附連結；所有推估標推估；內部完整資料不離開隊內。第三方照實寫：底圖伺服器看得到瀏覽範圍，GitHub Pages 有連線紀錄，不宣稱「完全不留紀錄」。若市府採用，依資通安全管理法做系統分級、依個資法做個資衝擊評估，寫進 100 天。

## 4. 想過但不做、保留的

| 點子 | 處置 | 一句理由 |
|---|---|---|
| 單一加權總分 | 不做 | 國外廢除中；臺北 382／435 里「中等」；會藏掉 72 個里 |
| 用海砂屋、黃單驗證模型 | 不做 | 海砂屋 70% 在內湖、士林、北投，和面積型模型無關（AUC 0.37） |
| 可瀏覽的列管地圖 | 不做 | 汙名化風險來自地圖；精確地址查詢不會 |
| AI 推估屋齡 | 不做 | 全球開放建物輪廓沒有臺灣；OSM 只有 0.7% 有年代 |
| 市場缺口地圖（里層級） | 保留 | 要地籍圖；現在只做到區層級，當一張圖加漏斗數字 |
| 建商誘因、民間代辦 | 保留 | 是政策建議，寫進 README；國外前提是流程標準化與責任歸屬 |
| 工地鼠患外溢 | 保留 | 和排序關係遠；資料顯示見鼠通報沒有集中在工地附近（5 個月資料，不能下定論） |
| 跨題整合 | 保留 | 票選只選一件作品，分散焦點 |

## 5. 差異化，一句話版

「別人告訴你這棟多老、這塊地會不會液化；市府自己也畫了 63 年前老屋和更新地區。我們多做三件事：把人老加進來、把一樓軟弱層加進來、不給總分而給排名區間。然後開一個市民能查自己家的入口，告訴他下一步找誰。」

## 6. 風險與對策

| 風險 | 對策 |
|---|---|
| 作品網址要能公開打開，內網 VM 只有 VPN 看得到 | 公開版放 GitHub Pages（gh-pages 分支放產出物）；VM 只給隊內看 |
| 規則寫「Day 1 起可開始寫程式」 | 賽前只做資料、設計稿、內部原型；Day 1 向主辦確認 |
| 全國 2026 版液化圖的服務沒有授權標示 | 公開版預設城市版；全國版只放里層級對照，連到官方站 |
| 公開網站被當成攻擊面或洩漏個資 | 純靜態、無後端、無帳號、不存查詢紀錄、地址不進網址；資料全是開放資料的彙總或官方已公開清冊；內部完整資料不上公開站 |
| 文資保存與重建衝突 | 文資標出來、另走程序，不剔除（國外沒有一國把文資剔出風險清單）：候選里與候選棟標「鄰近文資」並寫下一步找文化局；送件前自動比對文資清冊（100 天建議） |
| 未判定偏向小棟老屋 | 鄰棟推估補到 68%；剩下的寫原因，退回里層級推估 |
| 被問「幾分算危險」 | 只給相對等級與排名區間，寫明「相對於臺北其他里」 |
| 公開風險資訊影響房價 | 兩份證據：政府研究報告說 2016 液化公告後中高潛勢區相對 −15.2%，6 個月後 −7.2%（R3）；我們自己用 20.9 萬筆實價登錄重算，高潛勢區 2016～2018 平均約 −5%，逐年都不顯著，2019 後消失（c8）。結論：短暫、小幅、三年內消失。卡片免責文字已寫好；不做可瀏覽清冊 |
