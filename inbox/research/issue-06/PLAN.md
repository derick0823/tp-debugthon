## 2. 痛點假設

題目要的是「讓市府科學化排出老屋健檢與公辦都更的優先順序」。往下拆，痛點可能落在 4 種角色身上。

| 編號 | 角色 | 痛點假設 |
|---|---|---|
| P1 | 市府（建管、都更） | 逐棟屋齡與構造不開放，排序缺乏依據。資料分散在棟、門牌、里、區 4 種尺度，接不起來。 |
| P2 | 市府（都更） | 危老重建靠市場。小基地、高齡住戶多、窄巷的地方不划算，沒人做，但這些地方可能最危險。 |
| P3 | 高齡屋主 | 不知道自家風險，也不知道下一步（老屋健檢、補助、液化自主檢查）。soil.taipei 10/31 關站，連查詢入口都要換。 |
| P4 | 消防與救災 | 窄巷、囊底路、液化區、行動不便的高齡者重疊的地方，地震後最難救。 |
| P5 | 所有人 | 資料版本不一：液化圖城市版與全國版差很多；官方說的「50 年以上老屋」用開放資料算不出來。 |
| P6 | 市府承辦人 | 排出優先順序之後，要由人去推。受訪的都發局公務員說，承辦人約一半時間在回覆議員與處理行政工作【訪談，2026-10-17】。案件跨很多單位，流程與資訊斷點連隊伍自己都不清楚。2026-10-18 新增，由 R4 調查。補充【訪談，2026-10-18，口徑待 debug-aa 核對】：12 個區各 1 位承辦，工作也跨區；大區一人手上約 100 多案，全市約 1,200 案（使用者補充：都更處、都更案；細的口徑待核對）；一線抱怨薪水不高。 |
| P7 | 前線協力廠商（外包） | 協力單位替承辦接電話、做初步文件分析；民眾的問題或抗議 10 分鐘內答不出來，才轉給承辦【訪談，2026-10-18，委外契約待 debug-aa 查】。前線手上沒有可以馬上回答的資料，每一通答不出來的電話都會變成承辦的負擔。2026-10-18 新增。 |

## 3. 資料規律假設

這些是用手上資料可以驗證的規律。由研究任務 R1 驗證。

| 編號 | 假設 | 用哪些資料驗證 |
|---|---|---|
| H1 | 「雙老」重疊：高齡比例高的里，屋齡也老、液化潛勢也高。集中在萬華、大同、中正等舊市區。 | 各里人口、房屋概況（區）、套繪圖（2001 年後新建比例）、實價登錄（建築完成年）、液化圖 |
| H2 | 主要的高風險存量是 1970～1990 年代的 4～5 層無電梯公寓。 | 建物棟數（樓層）、使照構造別 57～94 年、實價登錄（建材、樓層、建成年） |
| H3 | 液化圖用城市版或全國版，里的排名會明顯不同。 | 兩版液化圖疊里界 |
| H4 | 危老核准案集中在地價高的區，和風險高的區錯開。 | 危老核准 1,059 案（1150210 版）、房屋概況、高齡人口 |
| H5 | 窄巷救災風險集中在山邊舊聚落（士林、北投、內湖），液化風險集中在盆地河岸。兩種風險在不同地方，一個加權總分會把它們混在一起。 | 消防通道清冊、狹小巷道、搶救困難場所、液化圖 |
| H6 | 已知的高風險建物（海砂屋 158 案、地震黃單 36 筆）落在模型高分的里。可以當驗證集。 | 海砂屋清冊、地震列管、門牌座標 |
| H7 | 資料缺口本身就是市政 bug：50 年門檻算不出來、逐棟資料只到 2001 年、液化查詢站關站。 | 所有資料的盤點結果 |

### R1 驗證結果（2026-10-17）

詳見 `research/issue-06/data-patterns/report.md`。

| H2 | 存量成立，風險排序無法驗證 | 4～6 層占全市 49.7%，幾乎都在 1990 年前蓋好。1971 年是磚造的斷點。 |

## 4. 解法方向（候選）

5 個方向可以單獨做，也可以組合。研究的結果會決定選哪個。

| 編號 | 方向 | 給誰用 | 對應痛點 |
|---|---|---|---|
| S1 | **可解釋的風險評級儀表板**：里層級，各因子分開顯示，權重可以調，看排名怎麼變 | 市府 | P1、P5 |
| S2 | **「我家危險嗎」地址查詢**：輸入地址，看液化、屋齡推估、窄巷、附近海砂屋與危老案，加上下一步（老屋健檢、補助、自主檢查表） | 屋主 | P3 |
| S3 | **市場缺口地圖**：風險高但沒有危老案的里，當公辦都更候選 | 市府（都更） | P2 |
| S4 | **資料債清單與 100 天開放建議**：市府要開放哪些資料（房屋稅籍屋齡、耐震初評結果），哪個局處、多少成本 | 市府 | P1、P5 |
| S5 | **救災可及性**：高齡＋窄巷＋液化重疊的地方，排防災演練或社區培力 | 消防、里長 | P4 |

整合者目前的傾向【推論】：S1 當核心，S2 當對外介面，S3 當亮點，S4 寫進 README 的「100 天落地」。研究結果出來前不定案。

R1 之後的修正【推論】：

- S1 要改形狀：因子分開顯示，不要只給一個總分；液化可以切換版本；每個里標樣本數或信心。理由是 H1、H3、H5。
  - 國際依據（R2 先報）：紐西蘭 2026-09 修法，放棄單一 %NBS 分數，改用「建物類型 × 地點」矩陣，2027-07-01 施行。內閣文件**預估**約 55%（約 2,900 棟）建物會移出列管【文件，MBIE 內閣文件 2025-09，整合者已抽查來源】。見 `world-practices/cases/nz-earthquake-prone-buildings.md`。
- S2 的資料支持最強：海砂屋、地震黃單是逐棟風險，面積型模型抓不到，地址查詢剛好補上。
- S3 在里層級還做不到，要先有地籍圖。區層級只有萬華一個例子。
- S4 的素材已經齊了（H7）。
- 「下一波雙老」可以當 S1 的一個預設視角，或 Demo 的故事線。

R2 之後的修正【推論】：

- S1 的屋齡因子改成「耐震規範世代」（依建成年分級），不要用屋齡線性加權。臺灣的斷點年已由 R3 找到（見上方 R3 一節）。
- S1 加權重滑桿與排名區間，顯示「不論權重怎麼調都在前面」的里。
- S2 每筆結果標「推估」或「已確認」，「未判定」是正式類別；液化用「兩版一致度」圖例。
- S4 的核心主張：「房屋稅籍彙總到里」，不要求開放逐棟資料，不碰個資。
- S5 從配角升級成候選亮點：國際上做得少，和題目的「人老」直接相關。
- 反面教材（不要做）：單一總分當唯一輸出、公開沒驗證的清冊、照意願或土地價值排序。

R3 之後的修正【推論】：

- 所有結果的定位改成「事前排序，給市府決定先去哪裡做正式評估」，不是「評估結果」。
- S1 候選因子加「一樓軟弱層」。
- S3、S4 的論述各有政府內部前例可以引用（R3）。
- P6（承辦人力）可能改變產品的使用者：如果市府的瓶頸是人力，工具要幫承辦人省時間，不只是排順序。等 R4。
